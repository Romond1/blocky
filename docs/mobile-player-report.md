## Detection, orientation and viewport

Automatic mode combines the primary coarse pointer, available fine pointer, `navigator.maxTouchPoints`, viewport width and actual pointer/keyboard use. It does not use user-agent strings. A real touch selects touch controls; mouse or movement-key use selects keyboard controls on hybrids. The welcome screen and pause menu provide persistent **Automatic / Touch / Keyboard & mouse** overrides. The portrait prompt also exposes this override.

Touch viewports narrower than 600 CSS pixels and taller than they are wide show the friendly rotation screen. Resize/visual-viewport changes update it automatically. Gameplay pauses while it is visible. Larger tablet viewports can enter normally; keyboard mode never shows it. Play attempts fullscreen and landscape locking only when the orientation lock API exists, catches unsupported/rejected requests, and retains the prompt fallback. This requests browser orientation; it cannot physically rotate a device. [Orientation API reference](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock).

Mobile has a separate unscaled layout with safe-area insets, large buttons, compact room/hero/treasure strips and a center kept available for the world. The canvas and touch controls prevent gameplay scrolling, selection and browser touch gestures; scrollable menus remain usable. [Pointer capture and cancellation reference](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events).

| Left analog stick | WASD / arrows | Camera-relative movement, diagonals, deadzone and proportional speed |
| JUMP | Space | Existing `Game.jump()` |
| ACTION | E | Existing `HeroTeam.interact()` and contextual help/use actions |
| HERO | Tab | Existing hero handoff; also completes the touch version of Room 2's switching lesson |
| Drag open right side | Hold left mouse and drag | Same yaw/pitch limits and camera-look tutorial event |
| Menu → Reset Room | R | Same room reset; preserves unlocks and collectibles |

No separate ABILITY button: Mia's running speed and Yuki's heavy lifting are already part of movement/interaction. Mouse-wheel zoom and F fullscreen remain on desktop. Touch retains the existing bounded default camera distance.

Each pointer owns its joystick, camera drag or action button. Releasing/cancelling/loss of capture returns it to neutral. Hero switching, reset, rotation and menu changes clear both input sources. Window blur, page hiding and tab changes clear input and pause until **Keep playing**. Movement, puzzles, companion and timers stop beneath the pause menu. ACTION gains a gold outline when a nearby/carry interaction is available; controls dim during unavailable/cutscene/handoff states. Introductory hints use the touch labels. Japanese room headings, goals, replay entries, tutorials and new menu instructions are translated without changing English puzzle words.

## Public HUD, replay and teacher tools

The public numbered room bar, Debug button and Reset All button are gone. The HUD keeps room name, short objective, current hero/ability, coins and Heart Shard progress. There is no health system to display. Secondary settings, replay, instructions and Reset Room live in the pause menu.

Room progress uses a versioned `be-a-hero:adventure` localStorage save alongside the unchanged `be-a-hero:economy` save. Completing an unlocked room unlocks its successor; final completion requires Room 10's actual Heart restoration. Reset Room and replay preserve progress. A reset asks for confirmation after block/puzzle work, but an untouched room resets immediately. Resetting never awards coins again.

Legacy migration uses saved collectible IDs only when they match the game's real definitions and room/type. It conservatively restores the highest room evidenced by those collectibles. A previous visit that left no saved evidence cannot be reconstructed; existing collectibles are still retained. No requested URL room number is treated as evidence. The production build limits URL/replay access to saved unlocks. Reload starts the highest reached room unless an unlocked replay room is requested. Storage failure falls back to a playable in-memory session.

The local Vite development server retains direct room URLs and guarded fixtures for automated tests; those requests do not grant saved unlocks. The deployed build has no fixture permission.

**Teacher access:** open Menu, tap the “Adventure paused” heading five times in succession, then enter **1001**. **Go to any room** lists all ten rooms, including **10. The Dragon’s Cave**; select one and press **Go to room**. Debug and **Reset All — TEST** are also available for that session. Teacher room visits and completion during those visits never grant player room unlocks. Public replay still lists only earned rooms; using it resumes ordinary progression. Hiding teacher tools after an inspection returns to the highest unlocked room and hides Debug. Reload closes the teacher gate and enforces the saved unlock limit. Reset All requires explicit destructive confirmation and clears only this browser's adventure/economy state.

This is a client-side convenience gate, **not authentication**. Its hardcoded PIN can be inspected, and localStorage is editable by its owner. There is no authenticated backend or operation that can reset another browser/player's data. Server authorization would be needed if account-wide privileges are introduced.

- Gate, visible basalt shoulders and collision now share the same orientation/dimensions. The inner-edge jump route is closed.
- Anti-crush logic can hold an existing opening; approaching closed bars cannot open the gate. A full movement regression verifies both heroes and Heart cannot bypass the purple plates.
- Wrapped-angle normalization makes the widened upper language gallery visibly match its actual floor.
- Existing pillars and construction cliff now have matching solid collision.
- Falling heroes cannot award a future checkpoint and recover beyond an unsolved sector.
- Follow-up: the second obstacle's pad now holds its six bridge slabs up continuously while either hero stands on it. Switching preserves the holder, so the other hero can jump across without a countdown. Stepping off lowers the bridge, and the HUD explains the cooperation step.
- Follow-up: the wall-side floor now reaches solid cave walls. The construction court is wider, and shared floor geometry removes coplanar ring/court/dock overlaps. Required crossings remain lava gaps.
- Follow-up: the carousel brake is on the open approach at (-19, -23). The two central final paths are replaced with a short bridge to an isolated Heart landing; players can pass the inactive entrance en route to the puzzles, then return when it opens.
- Heart pickup by either hero, carrier preservation during switching, independent lava recovery, ferry/lift transport, altar gating and explicit ending choices were inspected and tested. They remain the existing systems.

The detailed audit, locations, evidence and proposed four-stage improvement are in [Room 10 repair report](mobile-room10-repair.md). Remaining issues: some camera angles are blocked by the tall carousel pillar; the six-slab crossing and revised untimed elevator need child/phone playtesting. Either hero can cross the held bridge; the ferry retrieves the waiting hero. The next story scene is still an event hook rather than supplied new content.

The separate proposal retains Heart → cooperative escape machinery → transport/construction/language → altar restoration. Further geometry tuning, additional picture hints, reduced language requirements, story content or rearranged sectors require your approval before implementation.

## Before deployment: real-device checklist

1. On Android Chrome and iPhone Safari, open fresh in portrait, rotate, choose either hero and press Play. Check browser bars/notches, orientation fallback and comfortable buttons on your smallest supported phone. Also try a tablet and keyboard/touch hybrid.
2. Hold the joystick while jumping/using ACTION, switch heroes while carrying, rotate during movement, switch apps/tabs, lock/unlock the phone, then resume. Confirm no stuck movement and paused timers.
3. Solve Rooms 1–2, use Room 3 help, then check later lifts/ferry/carousels with touch. Replay only reached rooms, reload and reset without losing treasures. Test teacher reset only in a disposable save.
4. Play all Room 10 sectors unassisted with a child: gate exchange, held bridge/ferry, untimed lift and optional block steps, language carousel, Heart recovery/placement and both choices. Judge instructions, camera angles and difficulty, not just technical completion.
5. Play for 10–15 minutes on a lower-powered phone; check heat, frame pacing, battery saver, audio/video loading and a slower connection. Full-session physical-device and child testing remain outstanding.
